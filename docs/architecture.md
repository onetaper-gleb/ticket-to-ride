# Архитектура Europe

Правила, боты и браузер используют TypeScript. React формирует выбор игрока, Three.js рисует стол и предметы. Ядро не зависит от DOM, кадров, хранилища и задержки бота.

## Модули

| Путь                    | Ответственность                                      |
| ----------------------- | ---------------------------------------------------- |
| src/shared/types.ts     | Состояние, наблюдение, команды, события и результаты |
| src/data/europe.ts      | Города, маршруты, билеты, цвета и таблица очков      |
| src/core/               | Чистые переходы, оплата, легальность и итог          |
| src/bots/               | Выбор команды по собственному наблюдению             |
| scripts/simulate.ts     | Выполнение матчей и проверка инвариантов             |
| src/session/            | Матч, очередь команд, боты и IndexedDB               |
| src/ui/                 | Выбор билетов/оплаты, объяснения и меню              |
| src/scene/              | Геометрия, поверхности, камеры и зоны ввода          |
| docs/ и .agents/skills/ | Текущие контракты, источники и приёмка               |

Владельцы назначаются в AGENTS.md и задании агенту. Интегратор меняет общие типы; остальные согласуют нужное изменение до кода.

## Ядро и публичные запросы

| Экспорт                                     | Контракт                                                              |
| ------------------------------------------- | --------------------------------------------------------------------- |
| createGame(options)                         | Создаёт воспроизводимый матч в setup                                  |
| applyCommand(state, command)                | Возвращает Transition; отказ сохраняет исходный state                 |
| getObservation(state, playerId)             | Возвращает изолированное наблюдение места                             |
| getLegalCommands(observation)               | Перечисляет доступные команды текущего места и фазы                   |
| getClaimOptions(observation, edgeId)        | Перечисляет допустимые составы оплаты участка                         |
| getStationOptions(observation, cityId)      | Перечисляет допустимые составы оплаты станции                         |
| getTunnelPaymentOptions(observation)        | Перечисляет допустимую доплату тоннеля                                |
| isRouteAvailable(observation, edgeId)       | Проверяет владельца и правило двойных линий для своего места          |
| getTicketProgress(board, playerId, tickets) | Выбирает одно общее назначение станций для всех билетов               |
| getLongestRouteLength(board, playerId)      | Вычисляет точный длиннейший путь без повторного использования участка |
| getGameResult(stateOrObservation)           | Возвращает состав очков, билеты и порядок мест                        |

Фазы: setup, action, draw, tickets, tunnel, finished. Команды: chooseTickets, draw, drawTickets, claim, buildStation, resolveTunnel, pass. Поля и точные сигнатуры принадлежат src/shared/types.ts и экспорту src/core/index.ts.

В setup игрок оставляет минимум два из четырёх билетов. В action начинается одно действие. draw хранит незавершённый второй добор; tickets — предложенные новые билеты; tunnel — базовую оплату, открытые карты и доплату. После завершения действия ядро передаёт ход автоматически.

Оплата использует конкретные cardIds. Варианты ядра описывают допустимые количества цветов и локомотивов. UI может выбирать другие физические карты такого же состава; ядро заново проверяет каждый ID, цвет и количество.

## Секреты и случайность

GameState принадлежит сессии. В Observation входят публичные города, владельцы линий, станции, счёт, размеры чужих рук и билетов, рынок и события. self содержит только свои карты и билеты. Чужие билеты раскрываются после finished.

Наблюдение не содержит порядок колод, rng, seed и чужие руки. Бот принимает только Observation. Симулятор может хранить полный матч для переходов, но не передаёт его в оценку решений.

Ядро получает seed и не читает часы. Браузер создаёт случайный seed для новой партии без кода. Одинаковый код и число игроков повторяют раздачу. Закрытые карты не показываются сцене.

## Сессия и сохранения

Сессия сериализует команды и сохраняет принятые переходы. Новый матч, восстановление и выход увеличивают sessionEpoch. Бот несёт epoch и revision; сессия отвергает запоздалый ответ.

AppProps.sessionId передаёт ту же идентичность интерфейсу. При смене сессии UI очищает выбор билетов, оплату, подсказки, правила и камеру. Совпадение setup и revision 0 не означает тот же матч.

Europe использует schemaVersion 2, rulesVersion europe-base-v1 и IndexedDB last-train-europe-v1 со store saves. Ключ current хранит обычную партию, tutorial — учебную. Записи выстраиваются последовательно; загрузка ждёт их завершения.

Сохранение включает незавершённый добор, предложенные билеты, попытку тоннеля и последние ходы. Черновой выбор объекта или отдельных карт UI не сохраняет. Неподдерживаемая версия отвергается с объяснением. Старая база эвакуационной версии остаётся нетронутой.

## 3D и ввод

TableInteraction передаёт намерение, TableView описывает доступные предметы и печать. Камера, подсветка и текстуры не списывают карты и не назначают владельца линии.

За столом курсор скрыт. zone-input выбирает крупную область, сохраняет логическую опцию по ID и переключает её относительным движением. Внутри области камера имеет закреплённую точку. Невидимый raycast карточек не используется.

В нейтральной области ЛКМ или пробел приближает карту. Здесь виден курсор; raycast выбирает города и линии. Пробел/Escape возвращает к столу. Жест проверяет ревизию и доступность; перетаскивание не становится подтверждением.

Карты показывают цвет и символ. Билеты показывают два города и стоимость. Лист объясняет выбранное действие, обязательный добор и доплату. Доска показывает очки и ресурсы игроков. DOM остаётся для меню, обучения, клавиатурных контролов и режима без WebGL.

Сцена ограничивает DPR и освобождает материалы, геометрию и текстуры. Ассеты имеют источник и hash в manifest; его обновляет интегратор.

## Онлайн

В текущем соло серверных комнат нет. Будущий сервер должен владеть матчем, персональными наблюдениями, правами места, повторными commandId, восстановлением и таймерами. Контракт соло не подтверждает готовность сетевого этапа.

## Проверяемые границы

Инварианты включают 110 уникальных карт с учётом pendingTunnel, 46 уникальных билетов во всех местах хранения, запас вагонов и станций, владение маршрутом и фазу действия. Длиннейший путь допускает циклы и повтор города, но не повтор вагона; заимствованные через станции линии в него не входят.

Симуляции проверяют конечность и легальность, браузер — действия, сохранение и читаемость. Технические исключения для патологического накопления карт перечислены в europe-rules.md. Из этих проверок не следует доказанный человеческий баланс.
