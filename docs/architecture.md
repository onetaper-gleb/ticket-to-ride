# Архитектура Europe

Правила, боты и браузер используют TypeScript. React формирует выбор игрока, Three.js рисует стол и предметы. Ядро не зависит от DOM, кадров, хранилища и задержки бота.

## Модули

| Путь                    | Ответственность                                      |
| ----------------------- | ---------------------------------------------------- |
| src/shared/types.ts     | Состояние, наблюдение, команды, события и результаты |
| src/data/europe.ts      | Города, маршруты, билеты, цвета и таблица очков      |
| src/core/               | Чистые переходы, оплата, легальность и итог          |
| src/bots/               | Выбор команды по собственному наблюдению             |
| scripts/simulate.ts     | Выполнение матчей и проверка инвариантов             |
| src/session/            | Матч, очередь команд, боты и IndexedDB               |
| src/ui/                 | Выбор билетов/оплаты, объяснения и меню              |
| src/scene/              | Геометрия, поверхности, камеры и зоны ввода          |
| docs/ и .agents/skills/ | Текущие контракты, источники и приёмка               |

Владельцы назначаются в AGENTS.md и задании агенту. Интегратор меняет общие типы; остальные согласуют нужное изменение до кода.

## Ядро и публичные запросы

| Экспорт                                     | Контракт                                                              |
| ------------------------------------------- | --------------------------------------------------------------------- |
| createGame(options, randomness?)            | Создаёт матч в setup с выбранным источником перемешивания              |
| applyCommand(state, command, randomness?)   | Возвращает Transition; отказ сохраняет исходный state                 |
| getObservation(state, playerId)             | Возвращает изолированное наблюдение места                             |
| getLegalCommands(observation)               | Перечисляет доступные команды текущего места и фазы                   |
| getClaimOptions(observation, edgeId)        | Перечисляет допустимые составы оплаты участка                         |
| getStationOptions(observation, cityId)      | Перечисляет допустимые составы оплаты станции                         |
| getTunnelPaymentOptions(observation)        | Перечисляет допустимую доплату тоннеля                                |
| isRouteAvailable(observation, edgeId)       | Проверяет владельца и правило двойных линий для своего места          |
| getTicketProgress(board, playerId, tickets) | Выбирает одно общее назначение станций для всех билетов               |
| getLongestRouteLength(board, playerId)      | Вычисляет точный длиннейший путь без повторного использования участка |
| getGameResult(stateOrObservation)           | Возвращает состав очков, билеты и порядок мест                        |

Фазы: setup, action, draw, tickets, tunnel, finished. Команды: chooseTickets, draw, drawTickets, claim, buildStation, resolveTunnel, pass. Поля и точные сигнатуры принадлежат src/shared/types.ts и экспорту src/core/index.ts.

В setup игрок оставляет минимум два из четырёх билетов. В action начинается одно действие. draw хранит незавершённый второй добор; tickets — предложенные новые билеты; tunnel — базовую оплату, открытые карты и доплату. После завершения действия ядро передаёт ход автоматически.

Оплата использует конкретные cardIds. Варианты ядра описывают допустимые количества цветов и локомотивов. UI может выбирать другие физические карты такого же состава; ядро заново проверяет каждый ID, цвет и количество.

## Секреты и случайность

GameState принадлежит сессии. В Observation входят публичные города, владельцы линий, станции, счёт, размеры чужих рук и билетов, рынок и события. self содержит только свои карты и билеты. Чужие билеты раскрываются после finished.

Наблюдение не содержит порядок колод, rng, seed и чужие руки. Бот принимает только Observation. Симулятор может хранить полный матч для переходов, но не передаёт его в оценку решений.

Ядро получает seed и не читает часы. Браузер создаёт случайный seed для новой партии без кода. Одинаковый код и число игроков повторяют раздачу. Закрытые карты не показываются сцене.

Необязательный CoreRandomness экспортируется из src/core/index.ts: `shuffle<T>(items: readonly T[]): T[]`. Доверенный caller возвращает новую перестановку всех переданных элементов, не меняя их содержимое. Аргумент передаётся отдельно в createGame и каждый applyCommand; он не входит в GameOptions, GameState, сохранение или Observation. Без него действует прежний seeded shuffle, включая порядок обновления rng. С ним все начальные колоды, перераздача сброса, открытие тоннеля и повтор/защитный reset рынка используют callback. Онлайн-сервер должен передавать криптографическое перемешивание при каждой команде и сохранять принятый конкретный порядок колод; один случайный seed или начальный pre-shuffle этого не заменяет.

## Сессия и сохранения

Сессия сериализует команды и сохраняет принятые переходы. Новый матч, восстановление и выход увеличивают sessionEpoch. Бот несёт epoch и revision; сессия отвергает запоздалый ответ.

После завершённого действия человека сессия сохраняет pendingTurn с ревизией и сообщением. Боты и повторные команды ждут подтверждения «Завершить ход»; оно снимает паузу, не выдавая дополнительного действия ядру. Подготовка, незавершённые добор/билеты/тоннель и финальный итог не создают такую паузу. Старые сохранения без pendingTurn продолжаются как раньше.

AppProps.sessionId передаёт ту же идентичность интерфейсу. При смене сессии UI очищает выбор билетов, оплату, подсказки, правила и камеру. Совпадение setup и revision 0 не означает тот же матч.

Europe использует schemaVersion 2, rulesVersion europe-base-v1 и IndexedDB last-train-europe-v1 со store saves. Ключ current хранит обычную партию, tutorial — учебную. До публикации принятого перехода сессия синхронно записывает snapshot в отдельный localStorage-журнал слота, затем ставит запись IndexedDB в последовательную очередь. Это сохраняет последний добор, билеты, тоннель и паузу End даже при немедленной перезагрузке. После завершения IndexedDB удаляется только совпадающая запись журнала; более новый snapshot сохраняется. Загрузка восстанавливает журнал, если асинхронная запись не успела завершиться. Если журнал записать нельзя, действие не принимается и интерфейс объясняет отказ.

Сохранение включает незавершённый добор, предложенные билеты, попытку тоннеля и последние ходы. Черновой выбор объекта или отдельных карт UI не сохраняет. Неподдерживаемая версия отвергается с объяснением. Старая база эвакуационной версии остаётся нетронутой.

## 3D и ввод

TableInteraction передаёт намерение, TableView описывает доступные предметы и печать. Камера, подсветка и текстуры не списывают карты и не назначают владельца линии.

За столом первый явный клик включает Pointer Lock и только захватывает мышь. Лишь следующий клик активирует выделенный предмет. Курсор скрывает браузер при фактическом захвате; при отказе он остаётся видимым, доступны повторный запрос и клавиатура. Esc только освобождает мышь, не открывает меню и не меняет вид. Фокус коллекции не зависит от абсолютных экранных координат. zone-input сохраняет логическую опцию по ID; vector-motion накапливает dx/dy из единственного потока mousemove.movementX/Y при захвате. pointermove и coalesced-события в этом режиме игнорируются; постоянные clientX/Y не измеряют жест. Невидимый raycast карточек не используется.

Согласованное движение в 48 px переключает соседнюю опцию. На границе логической сетки жест в 144 px переводит фокус к соседней разрешённой коллекции. neighborFocusZone выбирает её по физической раскладке стола и InputPolicy. Запрещённая коллекция не перехватывает фокус.

vector-motion требует доминирования одной оси над другой в 1,4 раза. Диагональ не переключает опцию. Мелкие события складываются; длинное событие расходует пороги по одному и сохраняет остаток. Разворот и пауза в 240 ms очищают прежнее направление. Стрелки переключают опции и коллекции без мыши. Движение и навигация не подтверждают игровые действия.

camera-motion хранит ограниченный отклик MouseLook отдельно от основного перехода камеры. Малое движение отклоняет вид вокруг текущего фокуса; после остановки отклик затухает к нулю. Расчёт по elapsedSeconds сохраняет длительность при разной частоте кадров. cameraFocusReady проверяет только основной переход, поэтому непрерывный отклик не блокирует клик. Во время нажатия и перетаскивания отклик закреплён. prefers-reduced-motion отключает его.

Накопленное движение, отклик и нажатие сбрасываются при уходе мыши, blur, скрытии страницы, resize, смене режима, сессии или настройки движения. При новом захвате движение начинается с пустого накопителя без скачка. На приближённом поле первое pointermove задаёт абсолютную исходную точку. Нажатие за столом учитывает сумму длин относительных смещений; путь больше 6 px запрещает клик, даже после движения туда и обратно. Меню и текстовые поля сохраняют DOM-ввод.

Пробел приближает разрешённое поле; из общего вида его открывает и ЛКМ. Здесь виден курсор, а абсолютные координаты нужны для raycast городов и линий. board-picking.ts отдаёт приоритет напечатанному названию города. На пересечении линий он выбирает ближайший видимый вагон среди фактически задетых маршрутов.

Колесо меняет приближение, drag перемещает поле и не подтверждает действие. Пробел возвращает к столу. Возврат не захватывает мышь автоматически: для этого нужен следующий явный клик. Esc освобождает мышь и оставляет текущий вид. Обучение разрешает осмотр поля по этапу и задаёт коллекцию для возврата.

ЛКМ активирует выделенный предмет; Enter делает то же при фокусе клавиатуры в игре. Нажатие проверяет revision, inputEpoch, sessionId, доступность и тот же объект при отпускании. Основной переход камеры не допускает подтверждения прежнего предмета. Автоматическая подсказка не переносит выбор на подтверждение; «Показать предмет» делает это по запросу.

Карты показывают цвет и символ. Билеты показывают два города и стоимость. Лист объясняет выбранное действие, обязательный добор и доплату. Доска показывает очки и ресурсы игроков. DOM остаётся для меню, обучения, клавиатурных контролов и режима без WebGL.

src/data/europe-geography.ts хранит отдельную географию для сцены. board-layout.ts строит кривые, равномерно размещает места для вагонов и подбирает подписи без пересечений. Сохранённые города и численные параметры правил остаются в src/data/europe.ts. TABLE_LAYOUT и TABLE_CAMERA согласуют физические области стола с приближениями. Общий вид отдаляется для узких окон; относительный ввод сохраняет направление независимо от соотношения сторон.

rail-miniatures.ts создаёт геометрию миниатюр; rail-batching.ts объединяет одинаковые детали в InstancedMesh и сохраняет interaction для каждого экземпляра. Карточная печать принадлежит card-art.ts; источники атласа описаны в europe-atlas-sources.md.

Сцена ограничивает DPR до 2 и освобождает материалы, геометрию, текстуры, экземпляры и карту окружения. Ассеты имеют источник и hash в manifest; его обновляет интегратор.

## Онлайн

ApplicationSession выбирает соло или сетевой режим. При входе по `?room` открывается комната; после создания комнаты её публичный код добавляется в URL, чтобы перезагрузка возвращала в тот же режим. Back удаляет код из адреса и возвращает отдельный GameSession с прежними current/tutorial сохранениями. WebSocket client создаётся в effect и освобождается при выходе. Внешние сервер и ICE задаются VITE_NETWORK_URL/VITE_NETWORK_ICE_SERVERS; на удалённой странице отсутствующий endpoint даёт явную ошибку. Test tone отключён в production wiring.

server/ владеет полным состоянием, криптографическим shuffle, очередью комнаты, правами места, SQLite журналом и таймером целого хода. src/network/ хранит типизированный протокол, персональный клиентский журнал и WebRTC audio; src/ui/network/ показывает лобби, соединение, срок хода и голос. Browser получает собственное Observation и authority. В runtime import graph от main нет Node/ws/SQLite модулей.

Сетевой enqueue не означает принятое действие. UI хранит черновик до accepted ack и соответствующего персонального snapshot. Отдельный optional Diorama.intentEpoch отменяет прежнее удержанное намерение при смене сетевого контекста без сброса камеры, масштаба и Pointer Lock. Реальная смена сессии использует прежний reset.

Локальная готовность требует общих проверок двух клиентов, восстановления и audio media flow. Соло-приёмка и статическая публикация этого не подтверждают. Внешние HTTPS/WSS, NAT и TURN — отдельная инфраструктура.

## Проверяемые границы

Инварианты включают 110 уникальных карт с учётом pendingTunnel, 46 уникальных билетов во всех местах хранения, запас вагонов и станций, владение маршрутом и фазу действия. Длиннейший путь допускает циклы и повтор города, но не повтор вагона; заимствованные через станции линии в него не входят.

Симуляции проверяют конечность и легальность, браузер — действия, сохранение и читаемость. Технические исключения для патологического накопления карт перечислены в europe-rules.md. Из этих проверок не следует доказанный человеческий баланс.

Pointer-lock controller подтверждает захват через document.pointerLockElement и pointerlockchange, а не разрешение Promise. plain requestPointerLock() использует обычные относительные смещения без требования raw input или fullscreen. Ошибка не скрывает курсор. Смена режима, сессии, blur, скрытие страницы, resize и cleanup освобождают собственный захват и отменяют нажатие. Поздний захват отменённого запроса освобождается. Клавиша Tab и фокус DOM позволяют работать с обычным курсором. Контракт событий и активации: [Pointer Lock 2](https://www.w3.org/TR/pointerlock-2/).

Памятка содержит общий набор rulesPages для DOM и физического листа. Назад и следующий лист не зациклены, «Вернуться к игре» сохраняет выбор и оплату. rulesOpen ограничивает ввод листом; закрытие восстанавливает разрешённую коллекцию. Иллюстрации подключаются по public/rules-illustrations/<id>.svg (DOM) и .png (CanvasTexture); id, caption и alt передаются отдельно. При отсутствии или ошибке остаётся полный текст. Подписки текстуры удаляются при dispose, поздняя загрузка не рисует на старом листе.
