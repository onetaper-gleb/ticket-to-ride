# Архитектура «Последнего рейса»

Игра использует TypeScript для правил, ботов, браузера и будущего сервера. React показывает панели, Three.js рисует макет. Состояние правил не зависит от рендера, кадров или сетевой задержки. Архитектура рассчитана на соло-MVP; онлайн добавляется отдельным этапом.

## Границы модулей

| Модуль | Владелец | Ответственность |
|---|---|---|
| `src/shared/types.ts` | Интегратор | Типы команд, состояний, наблюдений, событий и результатов |
| `src/core/**`, `src/data/**` | Агент ядра | Переходы состояния, легальность, маршруты, прогноз, очки, сценарий |
| `src/bots/**`, `scripts/simulate.ts` | Агент ботов | Выбор команд из разрешённого наблюдения, симуляции |
| `src/ui/**`, `src/scene/**` | Агент интерфейса | Панели, ввод, камера, 3D, анимация событий |
| `src/session/**` | Интегратор | Владение матчем, запуск ботов, сохранение и восстановление |
| `src/network/**`, `server/**` | Агент сети после соло-MVP | Комнаты, сессии, WebSocket, SQLite |
| `.agents/skills/**`, эти документы | Архитектурный агент | Процесс, роли и проектные навыки |

Пути могут уточняться интегратором вместе с таблицей. Один файл имеет одного активного владельца. Агент сообщает владельцу о нужной правке, а владелец вносит её либо явно передаёт файл. Проверяющий читает все модули, но меняет только переданные ему файлы.

## Ядро и наблюдения

Ядро реализует чистый переход: состояние и команда дают новое состояние и события либо отказ с причиной. Только этот переход списывает карты, меняет поезда, груз, очереди, очки и фазу. Отклонённая команда не меняет состояние. Предпросмотр маршрута использует те же расчёты, что исполнение.

Полное состояние принадлежит локальной сессии, затем серверу. Наблюдение игрока содержит публичную карту, прогноз, рынок, приказы, очки, количество чужих карт, собственную руку и задания. Оно исключает чужие руки, задания, закрытую колоду и внутреннее состояние случайности. Бот получает то же ограниченное наблюдение. Передача полного состояния «только для оценки» нарушает контракт.

`src/shared/types.ts` фиксирует точные имена API. Модули читают его перед работой и согласуют изменения через интегратора. Типы наблюдений создаются явным перечислением разрешённых полей. Копирование полного состояния с последующим удалением нескольких секретов не задаёт надёжную границу.

| Экспорт | Контракт |
|---|---|
| `core.createGame(options)` | Создаёт `GameState` в фазе `setup` |
| `core.applyCommand(state, command)` | Возвращает `Transition` с новым состоянием, событиями или ошибкой |
| `core.getObservation(state, playerId)` | Возвращает `Observation` для указанного места |
| `core.getLegalCommands(observation)` | Перечисляет разрешённые команды по наблюдению |
| `core.previewOrder(board, train, order)` | Возвращает `RoutePreview` по публичной карте |
| `core.getGameResult(stateOrObservation)` | Возвращает `GameResult` |
| `bots.chooseBotCommand(observation, difficulty)` | Возвращает одну `GameCommand`; по умолчанию уровень `normal` |
| `ui/App.tsx` | Default export принимает `AppProps`; callbacks вызывает сессия |

Фазы контракта: `setup`, `action`, `draw`, `discard`, `orders`, `finished`. В `setup` каждая бригада оставляет два из трёх районных заданий через `chooseObjectives`. Сессия затем запускает обычный ход. После первого добора состояние хранит `drawsRemaining`; оно входит в наблюдение и сохранение.

## Время и случайность

Поезд находится на станции. Движение, обслуживание и затопление рассчитывает ядро в порядке фаз. Three.js только показывает принятые события. Один обычный шаг проходит до второго шага экспресса. Погрузка, выгрузка или прибытие на позицию прекращает движение поезда в этом раунде.

Волна приходит после движения. Станция, закрываемая после раунда F, допускает выезд в F, но обычная погрузка безопасна не позднее F−1. Экспресс не выезжает в том же раунде после погрузки. Затопленный поезд недоступен до конца матча. Инициатива берётся из сценария, а не рассчитывается простой ротацией.

Локальное ядро использует воспроизводимую случайность. Сессия создаёт случайный seed перед инициализацией, если игрок не ввёл свой. В ядре нет чтения часов. Seed и версии сценария сохраняются с матчем. Бот получает отдельную случайность для выбора между допустимыми вариантами. Онлайн закрытую колоду перемешивает сервер криптографическим генератором; публичный seed её не раскрывает.

## Сессия и поздние ответы

Сессия последовательно принимает команды. После принятого перехода она сохраняет состояние и обновляет наблюдения. Локальное хранилище получает версию схемы, сценария и правил. Неподдерживаемая версия не пересчитывается молча текущими правилами.

В соло асинхронный запрос боту несёт sessionEpoch и revision. SessionEpoch меняется при новой партии, продолжении и выходе в меню; revision — после каждой принятой команды. Ответ принимается только при совпадении обоих значений. Для онлайн к ним добавятся matchId, turnId и controlEpoch, различающие матч, ход и передачу управления. Отмена запроса сама по себе не заменяет эту проверку.

В браузере бот работает в Web Worker, когда измерения требуют вынести расчёт. Начальная реализация может выбирать ход синхронно при малом бюджете. Контракт наблюдения и защита поздних ответов сохраняются при обоих вариантах.

## Онлайн после MVP

Сервер владеет матчем и проверяет полномочия, revision, turnId, controlEpoch, фазу и легальность. Повтор `(matchId, seatId, commandId)` возвращает прежний результат без повторного списания. Тот же ID с другим содержимым отклоняется. Новая попытка после отказа использует новый ID.

SQLite сохраняет состояние, журнал и подтверждение команды одной транзакцией. Рассылка происходит после commit и содержит персональное наблюдение. При аварии восстанавливается последний commit. Сервер сериализует команды комнаты и атомарно назначает места.

Таймер охватывает весь ход, включая второй добор и приказы. Бот после timeout завершает оставшуюся фазу. Возвращение человека происходит на границе его хода и увеличивает controlEpoch. Если отключились все люди, матч приостанавливается. Перезапуск сохраняет фазу и выдаёт новый бюджет хода.

## Данные и графика

Баланс и карта лежат в конфигурации с версиями. Изменение чисел не вводит скрытую помощь игроку. Путь для движения выбирает ядро; декоративный сплайн принадлежит сцене.

Соло-MVP использует процедурные модели и общую палитру. Любой внешний ассет получает источник, лицензию, преобразования и hash в manifest. Генерация растровых референсов не заменяет 3D-модель. Платные сервисы не нужны для MVP.

Проверяемые границы готовности описаны в [процессе разработки](development.md).
