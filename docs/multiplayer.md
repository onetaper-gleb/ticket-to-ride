# Europe: локальный сетевой этап

Документ описывает реализацию в `server/`, `src/network/` и `src/ui/network/`.
Правила остаются классическими Europe 2019: [правила](europe-rules.md),
[границы ядра и интерфейса](architecture.md). Сетевой сервер владеет матчем,
клиент показывает персональное наблюдение и отправляет намерение игрока.

Этот этап проверяется локально. Основной выпуск Sites с ним ещё не опубликован. Наличие сетевого preview не означает, что публичный адрес игры предоставляет комнаты.
Публикацией, интеграцией меню и финальной приёмкой управляет интегратор.
Проект использует собственный код, обычный Git/GitHub и публичные открытые зависимости;
запрет внутренних инструментов и инфраструктуры из [AGENTS.md](../AGENTS.md) обязателен.

## Запуск с чистого checkout

Для сервера нужен **Node.js >=24.19.0** с `node:sqlite`; фактически проверен 24.19.0.
Менеджер пакетов — pnpm 11.25.0. Node 22 из прежних инструкций соло для этого сервера не входит в проверенную конфигурацию. Команды ниже выполняются из корня проекта.

```sh
node --version
pnpm install --frozen-lockfile
pnpm --dir server install --frozen-lockfile --ignore-workspace
pnpm check
pnpm --dir server check
```

У сервера свой `server/pnpm-lock.yaml`. Его `start` использует `tsx` из корневых
зависимостей, поэтому нужны обе установки. Дополнительный runtime-сервис не требуется:
SQLite входит в Node; WebSocket-сервер использует публичный `ws` 8.22.0, лицензия MIT.

В первом терминале запустите сервер, во втором — отдельный сетевой preview:

```sh
pnpm --dir server start
```

```sh
node --import tsx scripts/network-preview.ts
```

Откройте `http://127.0.0.1:5177/` в двух независимых вкладках или профилях.
Создайте комнату, скопируйте приглашение и войдите вторым именем. Preview использует
`src/network/preview.tsx`; это отдельная точка входа для проверки сетевого UI.
Обычный `pnpm dev` запускает основной интерфейс на 5173 и сам сервер комнат не запускает.

## Конфигурация сервера

CLI находится в `server/main.ts`, транспорт — в `server/transport.ts`.

| Переменная               | Значение по умолчанию      | Ограничение                              |
| ------------------------ | -------------------------- | ---------------------------------------- |
| `EUROPE_HOST`            | `127.0.0.1`                | Адрес привязки HTTP/WebSocket            |
| `EUROPE_PORT`            | `8787`                     | Целое 1–65535                            |
| `EUROPE_DB_PATH`         | `server/data/rooms.sqlite` | Частная SQLite база                      |
| `EUROPE_ALLOWED_ORIGINS` | Список ниже                | Origins через запятую, пробелы убираются |
| `EUROPE_BOT_DELAY_MS`    | `180`                      | Целое 1–60000, задержка шага бота        |

Разрешены `http://localhost:5173`, `http://127.0.0.1:5173`,
`http://localhost:5177`, `http://127.0.0.1:5177`.
Origin сравнивается целиком; Origin вне списка отвергается при upgrade.
Отсутствующий Origin разрешён только при привязке сервера к loopback.
WebSocket принимает пути `/` и `/ws`; `GET /health` возвращает `{ok:true,protocol:1}`.
Размер входящего пакета ограничен 65536 байт; бинарные и некорректные JSON отклоняются.
Heartbeat раз в 15 секунд обнаруживает пропавшие соединения.

`createRoomServer({host,port,dbPath,allowedOrigins,botDelayMs,turnBudgetMs})` возвращает
`{url,service,close}`. `port:0`, `:memory:` и переопределение `turnBudgetMs` нужны тестам;
CLI порт 0 и отдельную переменную для бюджета не предоставляет.
`SIGINT`/`SIGTERM` ждут закрытия сервиса и базы. Стартовые ошибки не печатают пакеты.

## Частная база и атомарность

`server/store.ts` использует WAL, `synchronous=FULL` и `BEGIN IMMEDIATE`.
Новый каталог создаётся с режимом 0700; файл базы, `-wal` и `-shm` получают 0600. Права уже существующего родительского каталога не пересоздаются.
База содержит полное скрытое состояние партии и не является публичным артефактом.

| Таблица                                       | Назначение                                                 |
| --------------------------------------------- | ---------------------------------------------------------- |
| `rooms(id,state)`                             | Последнее принятое частное состояние комнаты               |
| `journal(seq,room_id,entry)`                  | Последовательность принятых событий и результатов запросов |
| `replies(scope,owner,actor,id,payload,reply)` | Долговечный ответ для повторного запроса                   |

Состояние, журнал и ответ фиксируются одной транзакцией **до** изменения памяти,
рассылки наблюдений и ACK. Ошибка записи откатывает все три изменения.
В памяти команды сериализуются по комнате; гонка за одно место даёт одного владельца.
Идентичность участника хранит hash секрета и lease соединения, а не открытый секрет.

Для game dedup ключ включает `scope=game`, `owner=JSON.stringify([roomId,matchId])`,
`actor=seatId`, `id=commandId`. Room dedup использует комнату, memberId и requestId.
Идентичный ID и канонический payload возвращают прежний ответ без второго применения. Тот же ID с другим payload отклоняется. Исторический собственный retry получает свой
ACK даже после изменения текущего хода; ID другой комнаты не может отравить этот ответ.
Старые game replies с owner=matchId мигрируют по подтверждающему событию журнала комнаты.

Первый `create`/`join` также атомарно сохраняет receipt: `scope=bootstrap`,
`owner=SHA256(bootstrapSecret)`, `actor=create|join`, `id=requestId`. Частичные UNIQUE
индексы разрешают один requestId и один hash proof. Payload исключает открытый proof;
reply содержит только roomId/memberId. Журнал содержит payload и hash, а не секрет.
Точное повторение восстанавливает первоначальное место, даже если первый WELCOME потерян
или сервер перезапущен. Неверный proof даёт `BOOTSTRAP_DENIED`; изменение ID, типа или
payload при прежнем proof — `BOOTSTRAP_REUSED`. Повтор на том же действующем socket
не меняет lease; новый socket восстанавливается обычным повышением lease и controlEpoch.

`server/game-random.ts` передаёт `cryptoShuffle` ядру при создании и каждой команде.
Fisher–Yates использует `node:crypto.randomInt`; начальный seed создаётся `randomBytes`.
Повторные перемешивания сброса и рынка также используют криптографический источник.
Конкретный принятый порядок колод сохраняется частно; клиент его не получает.

## Протокол 1

Канонические типы находятся в `src/network/protocol.ts`, проверка входа —
в `server/validation.ts`. Все ID и секреты в примерах ниже — placeholders.
Рабочие resume credentials, SDP, ICE credentials и порядок колод в отчёты не добавляются.

Handshake `create`, `join`, `resume` содержит `protocol:1` и `requestId`.
Для первой попытки create/join клиент создаёт CSPRNG proof: 32 байта, 64 lowercase hex
символа. Весь исходный packet сохраняется частно до socket/send; повтор сохраняет его ID
и proof. Resume использует сохранённый credential и новый requestId соединения.
Создание задаёт `settings`: 2–5 мест, `easy|normal`, 30–600 секунд, `admissionOpen`.
Имя очищается от управляющих символов и ограничивается 30 символами на сервере.

```ts
{ type: 'create', requestId: '<request>', protocol: 1, bootstrapSecret: '<private-64-hex>', name: 'Игрок',
  settings: { seats: 3, difficulty: 'normal', turnSeconds: 180, admissionOpen: true } }
{ type: 'join', requestId: '<request>', protocol: 1, bootstrapSecret: '<private-64-hex>', name: 'Друг', code: '<public-code>' }
{ type: 'resume', requestId: '<request>', protocol: 1,
  credential: { roomId: '<room>', memberId: '<member>', secret: '<private-secret>' } }
```

`welcome` возвращает адресату credential и персональный `RoomSnapshot`. Credential не входит в `RoomView`, последующие snapshot или рассылку другим участникам.
Приглашение содержит только публичный код: `?room=<public-code>`.
Код даёт доступ к свободному месту в открытом лобби; занятую идентичность возвращает resume.

`RoomSnapshot` содержит публичную комнату, собственный memberId, `authority`,
персональное `observation`, `result`, собственный `pendingTurn` и серверное `canAct`.
Ядро формирует наблюдение для места: чужие руки и предлагаемые билеты исключены;
порядок колод и случайность исключены; билеты соперников раскрываются в финале.
`observation.revision` в сети соответствует authority, а не локальному счётчику ядра.

Игровая команда обязательно несёт **все** координаты показанного состояния:

```ts
{ type: 'command', envelope: {
  matchId: '<match>', seatId: 0, commandId: '<command>', revision: 12,
  turnId: '<turn>', controlEpoch: 3, command: { type: 'draw', source: 'deck' }
} }
{ type: 'command', envelope: {
  matchId: '<match>', seatId: 0, commandId: '<end-command>', revision: 13,
  turnId: '<turn>', controlEpoch: 3, command: { type: 'endTurn' }
} }
{ type: 'ack', ack: {
  commandId: '<command>', accepted: true, revision: 13, roomRevision: 20
} }
```

Сервер проверяет принадлежность места, lease, матч, revision, turnId, controlEpoch,
паузу, контроль, deadline и фазу; легальность и оплату затем проверяет ядро.
ACK отказа содержит `accepted:false`, `code` и безопасное объяснение.
Dedup уже зафиксированной команды проверяется до проверки устаревшей authority.
Клиент не подставляет новую authority в старое намерение.

Административный запрос также привязан к показанной комнате и её общей ревизии:

```ts
{ type: 'room', requestId: '<request>', roomId: '<room>', revision: 20,
  action: { type: 'endMatch', matchId: '<shown-match>', confirmed: true } }
{ type: 'roomAck', requestId: '<request>', roomRevision: 21 }
```

Все room actions требуют актуальную room revision. Только собственный `leave`
допускает более старую ревизию при сохранённых roomId, членстве и lease.
Это позволяет выйти после обновления комнаты и не даёт дополнительных прав ведущего.
`sync` запрашивает новое персональное наблюдение. `error` может содержать requestId.
`kicked` завершает право восстановления; terminal resume ошибки —
`ROOM_NOT_FOUND`, `MEMBER_REMOVED`, `RESUME_INVALID`.

## Комнаты и ход

В лобби можно выбрать свободное место, отметить готовность, скопировать приглашение. Ведущий меняет размер, сложность, бюджет, admission и заменяет свободные места ботами.
Настройки и смена места сбрасывают готовность затронутых участников.
Старт возможен, когда все места заняты человеком или ботом, все люди подключены и готовы.
В новую играющую комнату по коду не входят; имеющий credential участник может восстановиться.

Ведущий ставит партию на паузу, снимает паузу, исключает другого участника или завершает
матч через отдельное подтверждение. Подтверждение хранит исходные roomId/revision/matchId;
диалог старого матча не должен завершить новый. Исключение и собственный выход также явные.
Выход/исключение в игре оставляют место боту и удаляют право resume; в лобби место свободно.
При отключении ведущего роль переходит подключённому участнику с наименьшим seatId.
При обычном финале доступны итог и возврат в лобби; принудительный endMatch убирает матч
без искусственного расчёта результата. Перед следующим стартом люди снова подтверждают готовность.

У человека **один deadline на полный ход**, включая второй добор, выбор билетов,
решение тоннеля и нажатие «Завершить ход». Завершённое действие создаёт `pendingTurn`;
authority остаётся у его владельца с `awaitingEnd:true`, даже если ядро уже выбрало следующего.
До явного `endTurn` нельзя добрать ещё карты или дать следующее действие другому человеку.
Начальный выбор билетов и незавершённые фазы отдельного pending End не создают.
Последнее действие всей партии сразу показывает итог, как текущий соло-контракт
`getTurnAcknowledgement`: при phase=finished отдельного End уже нет.

`ConnectionBar` показывает владельца authority, ожидание End и остаток полного бюджета.
Часы используют серверный epoch-ms deadline и клиентский `Date.now()`; точность при
рассинхронизации часов не измерена. Часы не озвучиваются каждую секунду; статус — polite.
Пауза ставит deadline=null и сохраняет остаток. Когда отключены все люди, сервер
автоматически замораживает партию; первый resume снимает только автоматическую паузу.
Явная пауза ведущего сохраняется после reconnect всех участников.

Истечение бюджета передаёт контроль боту даже у подключённого человека. Бот завершает текущий добор, билеты или тоннель; pending End передаёт ход без нового действия.
Смена контроля увеличивает controlEpoch; старые socket и timer результаты отвергаются.
`returnPending` возвращает подключённого человека **в начале следующего собственного хода**.
При restart сохраняется зафиксированная фаза, все люди сначала offline, а бюджет после
восстановления выдаётся заново. Это отдельная политика от паузы живого сервера.

## Клиент и физический интерфейс

`createNetworkClient(options)` использует native WebSocket; URL по умолчанию —
`ws://127.0.0.1:8787`. `options` также допускает storage/socketFactory для тестов,
reconnectDelays, requestTimeoutMs и makeId. По умолчанию ACK ждут 12 секунд;
повторы соединения ограничены задержками 250, 500, 1000, 2000, 4000, 8000 ms,
затем остаётся явная кнопка повторного соединения.

| API                            | Контракт                                                                   |
| ------------------------------ | -------------------------------------------------------------------------- |
| `getState`, `subscribe`        | Состояние соединения, snapshot, pending, error; unsubscribe обязателен     |
| `create`, `join`, `reconnect`  | Вход или восстановление собственной идентичности                           |
| `command(command, expected)`   | ExpectedCommand со всеми пятью координатами; boolean означает отправку     |
| `roomAction(action, expected)` | ExpectedRoom={roomId,revision}; права решает сервер                        |
| `clearError`                   | Убрать локально отображаемую ошибку                                        |
| `leave(expectedRoomId?)`       | Явный выход и удаление собственного журнала; guard защищает другую комнату |
| `dispose`                      | Закрыть socket, таймеры и подписки, сохранив журнал для resume             |
| `sendVoice`, `subscribeVoice`  | Адресный signalling; доступ проверяется сервером                           |

Per-tab `sessionStorage` хранит исходный bootstrap, затем credential и pending envelopes под ключом
`europe-network-v1:<server-url>`. Запись происходит **до** send; ошибка хранения не
разрешает отправить новое действие. Журнал связывается с сервером, комнатой и участником.
Reload восстанавливает pending запрос с прежним ID и payload. Credentials и proof не идут в URL/логи.
WELCOME заменяет bootstrap на собственный credential в журнале до connected. Если запись
не удалась, клиент сохраняет исходную попытку для восстановления и не разрешает новый вход.
Ошибка чтения журнала также блокирует fresh create/join, чтобы не перезаписать неизвестную
попытку. `BOOTSTRAP_DENIED`, `BOOTSTRAP_REUSED`, `ROOM_UNAVAILABLE`, `ROOM_FULL`,
`MEMBER_REMOVED`, `ROOM_NOT_FOUND` завершают попытку и разрешают новый явный вход.
Неизвестный ответ и `SERVER_ERROR` сохраняют packet для ручного reconnect.
Поздние события прежнего socket отсекает generation; старые snapshots не откатывают UI.

Pending game очищается лишь после совпавшего принятого ACK и snapshot с достаточными
observation revision **и roomRevision**. Это необходимо и для End, где новая общая
ревизия может быть единственным свидетельством передачи хода. `confirmedCommandId`
сигнализирует принятую команду вместе с её snapshot; UI использует его для очистки черновика.
Один boolean из `command` сам по себе не подтверждает расход карт или сохранение билетов.
Pending room action также ждёт matching ACK и его общей ревизии, без оптимистичной смены места.

`networkGameProps` захватывает показанную authority для callbacks и проверяет sessionId.
`NetworkGame({client,onBack,iceServers?,allowTestTone?})` подключает существующий `App`,
компактный ConnectionBar, RoomLobby и VoicePanel. Локального GameState у него нет.
Смена комнаты/матча/места/контроля сбрасывает UI-сессию. Отдельный interactionEpoch
включает connection, authority, pause, canAct, pending IDs и открытие комнаты;
App передаёт его через `Diorama.intentEpoch`. Он отменяет удержанное нажатие и capture
без сброса камеры, масштаба, focusZone, Pointer Lock или черновика. Большой reset остаётся
только сменой sessionId. По умолчанию solo не передаёт intentEpoch.
Client state дополнительно хранит локальный монотонный `intentEpoch`: он растёт до каждой
попытки command/roomAction и нового соединения. Поэтому отмена сохраняется в финальном
render даже при синхронном отказе journal и объединённых React обновлениях pending→null.
Токен не входит в wire protocol или частный resume journal.
Управление комнатой открывается поверх стола, блокирует ввод игры и возвращает фокус в диалог.
Соло-слоты `current` и `tutorial` в `last-train-europe-v1` сетевой матч не переписывает.
Владелец точки входа должен закрывать client при размонтировании/pagehide; VoicePanel
отдельно освобождает peer connections, media tracks, AudioContext и подписки.
RoomVoice также прямо подписывается на window pagehide и синхронно выполняет dispose;
ожидание React passive cleanup не требуется. Повторный dispose безопасен; поздний
getUserMedia останавливает полученные tracks. Resume journal при этом сохраняется.

## Голос и локальная диагностика

Голос использует WebRTC mesh между подключёнными людьми комнаты: одна пара на собеседника.
Сервер пересылает только адресный signalling внутри аутентифицированной комнаты.
`description`, `candidate`, `state`, `leave` несут generation; старое поколение игнорируется.
На входе микрофон выключен. Запрос `getUserMedia` возникает после явной кнопки; отказ не мешает игре. Есть mute и громкость каждого собеседника, speaking indicator,
повторное разрешение playback после autoplay block. Запись аудио не реализована.

`iceServers` передаётся в NetworkGame/VoicePanel/createRoomVoice; по умолчанию список пуст. В проверенных двух вкладках встроенного браузера без ICE-сервера RTP оставался нулевым.
С собственным локальным STUN и синтетическим сигналом 440 Гц подтверждены настоящее
соединение WebRTC, рост RTP bytes и входящей audio energy между двумя вкладками.
Это проверка media flow без аппаратного микрофона, без NAT и без внешнего хостинга. Аппаратный запрос/отказ разрешения проверен только unit-окружением; реальная проверка ещё нужна.

```sh
node --import tsx scripts/network-stun.ts --probe
node --import tsx scripts/network-stun.ts
```

Вторая команда держит собственный UDP responder на `127.0.0.1:3478`;
`EUROPE_STUN_PORT` меняет порт помощника. Он реализует ограниченный IPv4 Binding
для localhost QA, не предоставляет TURN, relay, TCP или внешнюю инфраструктуру.
Preview включает его только на localhost/127.0.0.1 через
`http://127.0.0.1:5177/?test-tone=1&local-stun=1`.
Тестовый звук также требует своей кнопки. При другом порте STUN интегратор передаёт iceServers. Параметр preview `server` задаёт публичный адрес WebSocket; приглашение сохраняет только room.
Диагностика показывает счётчики, состояния ICE и тип выбранной пары, без SDP, адресов и credentials.

## Проверки и оставшаяся приёмка

```sh
pnpm --dir server test
pnpm test
pnpm check
pnpm --dir server check
pnpm format:check
pnpm build
node --import tsx scripts/network-smoke.ts
node --import tsx scripts/network-recovery.ts
node --import tsx scripts/network-bootstrap.ts
pnpm simulate --count=25 --players=all --difficulty=mixed
```

Smoke обращается к уже запущенному серверу; `EUROPE_WS_URL` меняет адрес. Четыре конечные партии на 2, 3, 4 и 5 местах прошли с native WebSocket и реальным client:
люди и боты, отдельная комната, гонка за место, отказ чужих admin actions,
персональные наблюдения и ручной End. Политику людей в этой проверке выбирал алгоритм;
этот результат не доказывает качество человеческого UX или баланс.

Recovery создаёт собственную временную SQLite базу и loopback port 0, затем удаляет их. Два restart того же порта сохранили частичный добор и pending End; действия до End отклонены.
Потерянный принятый ACK и reload client восстановили byte-exact envelope без второго добора. Явная пауза сохранилась после закрытия обоих transport. 46 welcome/snapshot проверены на приватность.
Автоматическая пауза без подключённого наблюдателя подтверждена **косвенно** сдвигом публичного
deadline; JSON результата явно помечает этот вывод как inference.

Bootstrap создаёт собственные временные SQLite/loopback port 0 и 4 lost WELCOME сценария:
create/join с restart и без него. Native socket действительно закрывается, клиент создаётся
заново с отдельным Storage-адаптером; повтор byte-exact, прежние room/member сохраняются.
12 отрицательных proof/payload/ID запросов не получили WELCOME или дополнительное место.
В финальном root прогоне бот при botDelay=400ms завершил шаг за 425ms во время
22 отклонённых ready запросов; 49 персональных пакетов прошли privacy checks.

Независимое ревью и 38 серверных тестов проверили изоляцию комнат, долговечный dedup,
атомарный rollback, исторический retry, поздние authority/timer, CSPRNG, восстановление
добора/билетов/тоннеля, бюджет, смену контроля, Origin и транспортные ограничения.
Большой root прогон до последних двух lifecycle исправлений: 296 тестов,
check/server check, format и build прошли. После исправлений синхронного journal отказа
и pagehide прошли 60 targeted network tests (client37/adapter4/voice19), check/format/build;
независимое ревью подтвердило закрытие обеих P2. Весь большой набор повторно не запускался.
100 конечных mixed симуляций сохранили инварианты. Четыре native сетевые партии завершились
(125/242/232/211 команд для 2/3/4/5 мест), 3323 персональных пакета проверены.
При браузерном повторном входе после reload подтверждены connected ICE, RTP bytes
и входящая energy в обоих направлениях; fresh room начинается с выключенным источником.
При kick/leave голосовой UI и DOM audio удаляются, у собеседника peer исчезает. Закрытие
PC/tracks/AudioContext дополнительно проверено контролируемыми unit тестами; аппаратный
микрофон не запрашивался. Окончательный выпускной SHA и регрессии после интеграции фиксирует интегратор.

Реальный keyboard добор сохранил focusZone=deck и cameraReady=true после ACK;
третий добор отключён, End включён и authority остаётся у игрока. Встроенный браузер
отклонил `requestPointerLock` с `UnknownError`. Поэтому физические down→Enter→NACK→up
и held down→disconnect/reconnect→up остаются в браузерной приёмке интегратора;
проверка narrow hook и unit сценарии не заменяют эти действия с рабочим Pointer Lock.

Сетевой этап пока локальный: внешний TLS/WSS deployment, TURN/NAT, лимиты создания комнат,
retention/очистка базы, socket rate limits и эксплуатация в недоверенной сети не подготовлены.
Origin allowlist и предел пакета не заменяют эти меры. Расхождение часов клиента и сервера
не измерено; сервер остаётся источником решения о timeout независимо от цифр UI.
Основной Sites project_id и owner-only аудитория сохраняются; этот документ не подтверждает
публикацию сетевой версии или готовность внешнего сервера.
