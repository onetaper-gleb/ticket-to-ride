# GitHub и процесс разработки

Репозиторий для исходников — [onetaper-gleb/ticket-to-ride](https://github.com/onetaper-gleb/ticket-to-ride). `origin` указывает на этот репозиторий, ветка `main` предназначена для проверенной версии проекта.

## Содержимое репозитория

Импорт объединяет существующую историю проекта и начальный коммит GitHub. Он сохраняет обе истории, включая прежние коммиты с автором Sites; переписывание истории и force push не используются.

Репозиторий хранит исходники, ассеты, документацию, конфигурацию, `pnpm-lock.yaml`, `AGENTS.md` и `.agents/skills/`.

`node_modules/`, `dist/`, локальные `.env*`, логи и результаты временных проверок исключены через `.gitignore`. Зависимости восстанавливаются из lockfile; статическая сборка создаётся локально.

## Локальная разработка

Игра использует TypeScript, React, Three.js и Vite. Для запуска нужны Node.js 22.12+ или 24 и pnpm 11.25.0. Команда `pnpm install --frozen-lockfile` восстанавливает зависимости без изменения lockfile, `pnpm dev` открывает сервер на `http://127.0.0.1:5173`.

Перед интеграцией проверяются форматирование, типы, тесты и сборка: `pnpm format:check`, `pnpm check`, `pnpm test`, `pnpm build`. Изменения правил и ботов требуют завершённых симуляций, изменения интерфейса — реальных действий в браузере. Полные критерии находятся в [разработке и приёмке](development.md).

Текущий объём — соло: один человек и 1–4 бота. Серверов и онлайн-комнат пока нет.

## Ветки, коммиты и ревью

Каждая задача выполняется в отдельной ветке от `main`. Интегратор назначает агентам конкретные файлы; один файл имеет одного активного владельца. Независимый проверяющий воспроизводит ошибки и граничные сценарии, интегратор соединяет изменения и проходит приёмку.

Коммит содержит одно законченное изменение. После проверок и ревью ветка объединяется с `main`; push сохраняет результат на GitHub. Для обсуждения изменений или ревью через GitHub используется pull request. Импорт исходников сам по себе не добавляет CI: проверки пока выполняются локально.

Автор новых коммитов определяется локальными настройками Git `user.name` и `user.email`. Право отправлять коммиты и ветки на GitHub зависит от отдельной авторизации: SSH-ключа или HTTPS credentials. Настройки автора не дают права push и не меняют авторов старых коммитов.

## GitHub и публикация игры

Push на GitHub и публикация в Sites — отдельные действия. Push не обновляет работающую игру. Выпуск выполняется после приёмки по [контракту выпуска](../.agents/skills/lt-release/SKILL.md).

Помощник загрузки исходников Sites отправляет commit по явному URL своего репозитория. Изменение `origin` не перенаправляет эту отправку в GitHub.

Для выпусков сохраняются Sites `project_id` — `appgprj_6ac8ec042a748191bdc462fa12445527` — и аудитория owner-only. Импорт в GitHub не включает новый выпуск Sites.
