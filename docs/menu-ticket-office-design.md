# Меню «Билетная касса»: производственная спецификация

Версия 3.1, 10 октября 2026. Выбран вариант 2; главный экран сравнения — 1672×941. Эта версия исправляет режим длинного текста и ошибок поверх v3 `8bdda31d0d57529607a59062611a61c9b234d1cf`. Обычная desktop компоновка и арт сохраняются. База ветки `design/menu-ticket-office-art` — `bea9743c7622a7806a3d9b6824a9d912b0a41b65`. Документ задаёт размеры native DOM и контракт его совмещения с физической рамой. Камера, модели и проекция принадлежат общему дизайнеру; production UI подключает интегратор.

Доска увеличена и поднята к исходному PNG. Desktop использует крупные подписи с засечками, простой знак EUROPE и четыре строки; декоративный subtitle убран. Пояснения сохранений остаются отдельным динамическим текстом. Фасад и доска имеют общий перспективный разворот. Подробная адаптация вторична; доступность действий сохраняется.

## Исходные boardRect и settingsRect

Координаты в CSS px от верхнего левого угла документа при scrollY=0. Это **непреобразованные внешние border boxes DOM**, передаваемые в `composition.layout(width,height,boardRect,settingsRect)`. Их x/y задают левую верхнюю опору, height — ориентир высоты левого края, x+width — горизонтальную опору правого края. После перспективной проекции фактическая рамка является четырёхугольником; её AABB может иметь другие x/y/w/h. Уже преобразованный `getBoundingClientRect()` нельзя передавать обратно в layout.

Рама доски занимает 12 px по каждой стороне в локальной системе DOM; непрозрачный фон начинается с inset12. Контент начинается с inset24, на 1920 — inset28. Settings — отдельная рамка6 px, контент inset12. Эти отступы также преобразуются перспективой и не обещают постоянную экранную толщину.

### Интерполяция desktop

Desktop: width≥1100 и height≥680. Сначала e=min(width,1920). Если e×941/1672>height+1, e=height×1672/941. Затем q=clamp(e,1280,1920), cx=max(0,(width−q)/2), cy=max(0,(height−q×941/1672)/2). Допуск1px сохраняет опорные 1280×720 и1920×1080 без сдвига из-за округления aspect.

Все величины линейно интерполируются отдельно на отрезках q=1280→1672→1920; значения в узлах:

| Величина | 1280 | 1672 | 1920 |
| --- | --- | --- | --- |
| board x−cx / y−cy / width | 46 / 38 / 420 | 60 / 50 / 510 | 69 / 57 / 580 |
| padding внутри 12px border | 12 | 12 | 16 |
| header / header gap | 96 / 16 | 136 / 12 | 164 / 18 |
| row, включая tutorial / gap | 76 / 6 | 94 / 8 | 103 / 10 |
| label / icon / icon margin / mark width | 26 / 36 / 2 / 300 | 32 / 44 / 4 / 370 | 36 / 48 / 4 / 414 |
| settings width / height / margin-left / gap | 340 / 76 / 50 / 14 | 390 / 98 / 65 / 9 | 448 / 112 / 75 / 16 |

Фиксированная desktop высота доски =24+2×padding+header+headerGap+3×row+tutorialRow+3×gap. Settings x=board.x+marginLeft, y=board.y+фиксированная высота+gap. Переносы и ошибки этих величин не меняют. Width>1920 использует ultrawide: центральная рабочая область1920, дополнительное место вокруг принадлежит окружению. Высота рабочего блока не масштабируется независимо по Y.

### Прокрутка действий на desktop

Внутри доски header остаётся над отдельным native scroll viewport действий. Его локальная высота =3×row+tutorialRow+3×gap+16:338/416/458px в узлах1280/1672/1920. В обычном меню содержимое помещается целиком. Длинные hints, сообщения обоих слотов и retry остаются в потоке внутри этого viewport. Строки сохраняют минимальную высоту и растут при переносе; текст ошибок не ограничивается числом строк.

Scroll viewport имеет padding8px и margin(headerGap−8px) −8px −8px. Вложенный nav не добавляет headerGap повторно. Эти отступы сохраняют обычные позиции строк и оставляют место для внешнего6px focus. Прокрутка только вертикальная: overflow-y:auto, overflow-x:hidden, overscroll-behavior-y:contain. Полоса прокрутки появляется при переполнении; её ширина8px, track=row, thumb=paper с border2px board. Ошибки и подписи переносятся внутри доступной ширины, включая место полосы.

Native Tab/Shift+Tab прокручивает сфокусированную кнопку в видимую область. Для строк/retry задан scroll-margin-block16px, для viewport scroll-padding-block8px. Focusin и повторное измерение после resize/изменения сообщения вызывают scrollIntoView(block:nearest,inline:nearest) у активной кнопки. Header, settings и подвесы не участвуют во внутренней прокрутке. У каждой retry aria-describedby указывает на сообщение её слота.

Narrow: 760≤width<1100, height≥760, aspect<1.25; x32, y=clamp(height×0.272,220,360), w=min(400,width−64). Остальные width≥760 — compact, x24/y40; width<760 — column, x16/y24. Compact/column w=min(360,width−32). Settings w=board.w−32, x=board.x+16, gap24 в narrow и20 в остальных. Продолжение обучения переносится в две строки; Минимальные обычные rows72/76/84px, tutorialRow100/106/116px, settings height64/64/72px и retry60/64/72px соответственно narrow/compact/column. Переносы могут увеличить любую строку; реальные размеры state=both указаны в таблице. Settings сохраняет≥52px на дальнем крае при проверенном ракурсе.

Текст и длинные коды используют overflow-wrap:anywhere. На desktop весь текст доступен внутренней прокруткой, внешняя доска не растёт. Документ получает min-height=max(viewportHeight,самая нижняя проецированная точка UI+32) и вертикальную прокрутку при необходимости. На узких preset прокручивается документ. Browser zoom меняет CSS viewport и выбирает preset заново. Пример640×360 подтверждает эффективный viewport, а не фактический zoom200% браузера.

## Физическая рамка и native DOM

Общий статичный ракурс: camera position(0.04,0.52,6.4), vertical FOV34°, yaw фасада27°. Ограничение v2 «screen-parallel, максимум1°» отменено. Settings лежит на той же фасадной плоскости, поэтому её верхний край может подниматься вправо ниже уровня камеры. Наклон текста следует физической плоскости целиком.

Потребитель использует общий API `projectCorners(width,height) → {board,settings}`; каждый quad перечислен **TL,TR,BR,BL**. Углы берутся с лицевой внешней геометрии board-frame/green и settings-frame/wood с учётом matrixWorld и толщины. `projectFrame()` возвращает AABB только для диагностики. В текущем общем решении лучи камеры пересекаются с фасадной локальной плоскостью z=0.04, повернутой вместе со зданием. Unproject четырёх точек на один фиксированный мировой Z не описывает такую плоскость.

Порядок обновления: снять старые CSS transforms → измерить исходные border boxes в документе → вызвать layout → получить фактические quad → применить `menuQuadCssMatrix(quadRelativeToSourceOrigin,width,height)` отдельно ко всей доске и ко всей табличке с transform-origin0 0. Labels, hints, retry, icons и native кнопки находятся внутри этих преобразований. Не переносить только текст, не заменять кнопки canvas hit zones. Canvas aria-hidden и pointer-events:none; dialogs находятся вне преобразованных родителей. Изменение содержания, fonts-ready и resize повторяют измерение. Проверочный consumer пропускает временный скрытый viewport1×1 и выставляет ready только после первого успешного кадра/metrics.

DOM должен совпадать с фактическими четырьмя углами с допуском≤2 CSS px; AABB не заменяет это сравнение. Текущий consumer измерил0.0113px на1672 и максимум0.0414px по восьми размерам. Метрика совпадения углов сама по себе не подтверждает клики.

В desktop/ultrawide consumer всегда показывает физические доску, settings и подвесы. Ошибки, retry, длинное обучение и документ с вертикальной прокруткой не включают замену CSS-рамами. Canvas находится в документе с position:absolute, поэтому при внешней прокрутке сохраняет совмещение с native рамами. В обычных desktop состояниях и проверенных ошибках документ помещается в viewport.

Только в narrow/compact/column при переполнении документа сохраняется прежний доступный режим: физические доска/settings/подвесы скрыты, CSS-рамы прокручиваются вместе с DOM, canvas остаётся fixed. Это минимум доступности узких окон, не утверждённая физическая компоновка этих preset. На desktop такой режим запрещён.

Root здания: position0, scale1, rotation.y27°; cashierRoot под cashierAnchor: position0, quaternion identity, scale1. Размер головы/хват/контакты принадлежат владельцу персонажа. Геометрию и disposal рамки/текстур задают владельцы bundles; этот документ не вводит второй владелец ресурсов. Внешний радиус8px, внутренний3px, кант1px, заклёпки9px внутри полосы12px — ориентиры локального оформления.

В узких окнах можно скрыть/обрезать поезд и дальние детали, сохраняя доступные действия; полный состав не требуется. Окружение не растягивается отдельно по X.

Лампа в текущем контрольном bundle пересекает верхний край высокой доски. Её перенос закреплён за владельцем окружения; высоту доски сохранять. Голова, нижняя панель/пол, ближний багаж, поезд, опоры и фон также дорабатываются прежними 3D владельцами. Этот пакет утверждает 2D компоновку на общем ракурсе27°, а не окончательную приёмку всей сцены. Оси мира:+Y вверх,+Z к зрителю; прилавок/cashierAnchor Y=0. Контакты проверяются после замены bundles без дополнительного root scale персонажа.

## Действия и состояния

Всегда четыре строки: «Продолжить», «Начать партию», «Обучение» либо «Продолжить обучение», «Правила». Затем «Настройки партии». No-save: продолжение disabled + «Нет сохранённой партии», янтарный акцент на новой партии; у обучения «До первого маршрута». Current: акцент продолжения, «Обычная партия». Tutorial: обычное продолжение disabled; учебное доступно с «До первого маршрута». Both: обе строки доступны независимо. Finished current: «Продолжить» + «Открыть итоги». Loading каждого слота: его действие disabled, «Проверяем сохранение…»; правила и форма доступны. Preparing game: «Готовим стол…», команды старта disabled; отдельный возврат при долгой загрузке. Error каждого слота: «Не удалось проверить сохранение» и отдельная DOM-кнопка «Повторить проверку» у этого слота; неизвестный слот не подписывается как пустой.

Error занимает место ниже соответствующей строки. На desktop остальные действия сдвигаются внутри scroll viewport; boardRect/settingsRect остаются фиксированными. В узких preset ошибка увеличивает высоту доски и сдвигает settings в потоке. Сообщение никогда не заменяет label. Retry:64px локальной высоты на desktop,60px в narrow,64px в compact,72px в column; текст24/23/24/27px. На текущем desktop ракурсе минимальная эффективная высота остаётся больше52px. Декоративный арт не содержит названий действий или статуса. Gallery показывает состояния данных отдельно от реальной session/storage.

Обычная строка: paper на row; primary: ink на accent. Hover: paper на hover, primary ink на paper. Press: primary ink на pressed, обычная paper на board; сдвиг ≤1 px. Disabled: disabled на board, без общей opacity. Focus: двойной контур ink 2 px + focus 3 px с зазором 3 px, видимый вокруг primary и обычной строки. Focus и hover могут сосуществовать; primary не получает keyboard focus автоматически. Reduced motion: мгновенный цвет, без сдвига. Длительность цвета 140 ms — рекомендация будущему этапу после принятия общего статичного кадра; текущая gallery переключает состояния мгновенно, без движения.

## Форма и правила

«Начать партию» и «Настройки партии» открывают один dialog «Параметры новой партии». Width=min(640px,viewport-32px), max-height=viewport-32px, overflow-y:auto. Бумага paper, текст ink, поля белые, граница row; body overlay `#172B25` с opacity0.66. Заголовок 28 px (compact24), обычный текст/labels20px. Кнопки/поля≥52px; padding24px (compact16). Все футеры в потоке; старт достижим прокруткой.

Поля: «Всего мест» 2/3/4/5 + «1/2/3/4 бота»; «Сложность ботов» Лёгкие/Обычные; «Ваше имя» maxlength24, default«Вы»; details «Код партии (необязательно)», maxlength64. Начальный размер3; выбранная сложность сессии. Пустое имя→«Вы», seed trim. «Назад» закрывает без запуска. «Сесть за стол» — единственный запуск. При current подпись «Сесть за стол — новая партия» и «Новая партия заменит обычное сохранение. Обучение сохранится». При unknown slot — предупреждение о возможной замене. Focus trap, Escape, возврат focus задаёт функциональщик.

«Правила» открывают существующий reader `src/ui/rules-pages.ts`, width=min(680px,viewport-32px), max-height=viewport-32px, внутренний scroll. Gallery использует существующий текст/иллюстрацию только для проверки размещения: это не новый дизайн памятки. «Назад», «Следующий лист», «Вернуться в меню» видимы/достижимы; черновик формы сохраняется.
