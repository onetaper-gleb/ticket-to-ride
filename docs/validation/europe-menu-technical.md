## Renderer и native меню

Named export `MenuDiorama` в `src/scene/Diorama.tsx` создаёт отдельный renderer меню. VSM установлен до первого draw; граф — RenderPass → SSAO с полной depth и половинным AO → depth X → depth Y → OutputPass → FXAA. Depth texture заимствована у AO. Composer передаёт физические размеры passes при resize/DPR; FXAA получает обратное физическое разрешение. DPR ограничен 2, near/far камеры — .1/80. Тело игровой функции Diorama, PCF и физический ввод сохранены побайтно.

Каждый pass освобождается один раз, затем освобождаются два ресурса SSAOPass, пропущенные его dispose в Three r180, composer, composition и renderer. Контекст меню закрывается через forceContextLoss: он больше не используется, а renderer.dispose оставляет встроенные GL caches. Abort и closed guard закрывают запоздавшую composition. Pagehide очищает сцену; persisted pageshow создаёт новую. Ошибка ассета или потеря контекста оставляет native меню и кнопку повторной загрузки.

`src/session/SessionMenu.tsx` переносит принятую native печать из sealed preview в scoped CSS, настоящие кнопки и modal dialog. Настройки передают прежний GameOptions: 2–5 мест, имя, seed и сложность. Правила берутся из прежнего rulesPages, welcome — из TutorialWelcome. GameSession показывает presenter, когда observation отсутствует; игровой App получает прежние callbacks.

App, network/server/room UI, shared, main, core/data/bots, package и lockfiles не изменены относительно сетевой основы. Внешние зависимости не добавлены. Работа использует только собственный проект, ordinary Git/GitHub и проверенные публичные OSS; внутренние материалы и сервисы Яндекса не использовались, в том числе через исполнителей.

| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |

| Уйти из меню во время загрузки либо повторить загрузку после ошибки ассета/контекста.                                                                                                       | Поздняя composition освобождается; listeners и ресурсы закрываются один раз. Current и tutorial имеют отдельные loading/error/Retry. Retry вызывает настоящее чтение соответствующего слота. Guards игровых команд, pending End и revision остались прежними.

## Проверка

На runtime 43c38e8 прошли build, check, server:check, format:check и все 316 tests в 29 файлах. Собственный Chromium 157.0.8098.0 проверил размеры 1280×720, 1672×941 и 1920×1080, DPR2, настройки, правила и клавиатурный фокус; menu → solo → menu → continue, отдельное обучение и reload двух сохранений. Проверены два настоящих Retry повреждённых journals, уход во время загрузки, намеренная ошибка ассета 503, потеря WebGL-контекста и успешный Retry.

Дополнительный браузерный проход подтвердил resize вместе с DPR1↔2 и три гонки настоящего IndexedDB чтения с задержкой доставки success callback на 7 секунд. Значения хранилища не подменялись. Два независимых browser storage contexts создали собственную QA-комнату, начали партию с разными приватными руками и билетами и восстановили комнату после reload.

После импорта 78c945e runtime a54302e прошёл build/check/format:check и проверку изменившейся сцены: реальный рендер, resize, DPR2, native focus/settings/rules, два Retry, уход во время загрузки и fallback после 503. Повторно проверены два независимых сетевых клиента и reload. Отдельный teardown до reload подтвердил потерю закрытого контекста меню и удаление canvas. Равенство всех GL create/delete counters не заявляется: оставшиеся встроенные ресурсы закрываются вместе с контекстом.

Неизменные menu → solo/continue/tutorial/saves и полные finite/voice/Pointer Lock suites после обновления композиции не повторялись. Независимый source review подтвердил точное совпадение 55 menu/public paths, 92 защищённых paths и четырёх файлов собственного renderer/session binding. Проверены новые роли материалов, ошибки clone/setup с Retry и ownership заимствованной depth; подтверждённых открытых P1/P2 в этой границе нет.

Проверены desktop размеры. Реальное помещение страницы в BFCache не доказано: проверен обработчик persisted pageshow. DPR-only override в Chromium/CDP не отправлял native change даже минимальному matchMedia control, поэтому реальная смена монитора или масштаб без resize не подтверждены. Физический Pointer Lock, аппаратный микрофон и Internet/NAT в этом проходе не повторялись. Художественная приёмка, адаптив и анимация остаются открытыми.

В обычном браузерном проходе нет application/page errors. Сохранился прежний favicon.ico 404 из неизменённого index.html; 503 относится только к намеренному тесту fallback. Vite сообщает о большом JS chunk; производительность и VRAM не аттестованы.

## Собственный QA-стенд

Стенд: `http://127.0.0.1:5185/`, WebSocket `ws://127.0.0.1:8898`, отдельная БД QA. Для повторного запуска в собственном checkout:

```sh
pnpm install --frozen-lockfile
pnpm server:install
EUROPE_PORT=8898 EUROPE_DB_PATH=/absolute/own-qa/rooms.sqlite EUROPE_ALLOWED_ORIGINS=http://127.0.0.1:5185 pnpm server:start
```

В другом терминале:

```sh
VITE_NETWORK_URL=ws://127.0.0.1:8898 pnpm build
pnpm exec vite preview --host 127.0.0.1 --port 5185 --strictPort
```

Порты должны быть свободны; чужие серверы и комнаты не останавливать. Эта работа не использовала прежние 5175/ws8788 и старую rooms.sqlite.

[Manifest](europe-menu-integration-manifest.json) связывает source/build hashes с новым browser proof и сохранёнными доказательствами 43c38e8. Полный отчёт, scripts, JSON и screenshots передаются в integration handoff.
